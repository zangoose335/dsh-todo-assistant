# P0-D0 拖拽可行性记录

- **日期**：2026-10-19
- **模式**：现有卡片直接拖到 DSH 输入框，不新增 drop overlay、不改 UI
- **结论**：原生 HTML5 拖拽到输入框可行；当前输入框会接收 `text/plain` 并插入草稿。无需先做自定义 drop 层。

## 观察到的事实

- 卡片列表里的卡片本身是 `draggable`；
- 把卡片拖到 DSH 输入框时，输入框会插入拖拽 payload 的 `text/plain`；
- 之前 payload 是内部 id，所以用户看到的是编号；
- 现已改为用户可见的引用：
  - `#6.24「有相关性的待办靠前排列」`
- 仍然只改草稿，不自动发送、不新建卡。

## 未验证 / 未实现

- Chrome/Safari、docked/floating 的完整矩阵未逐项记录；
- 触摸设备不支持原生拖拽；
- 还没有 D1 的完整上下文 drop 层（自定义 JSON payload、按 id 拉详情、2000 字上下文）；
- 还没有 D3 的按钮/复制降级。

## 与 D1 的关系

这次只验证了“原生拖拽能到输入框”和“payload 应是可见引用”。

D1 仍需要：

1. 卡片拖拽 payload 区分卡片 id 和可见文本；
2. drop 后按 id 拉最新详情，插入完整任务上下文；
3. 不自动发送、不建卡；
4. 按钮/复制降级。

## 当前产品决策（2026-10-19）

- 原生拖拽只插入用户可见的卡片引用（如 `#6.24「…」`）；
- 详细上下文由 AI 读取卡片获得，不在 drop 时自动展开；
- 完整正文插入继续使用现有三个按钮（引用此待办 / 插入任务简报 / 新会话中立即执行）；
- D1 的“拖拽后插入完整上下文”不再作为当前实现目标；D2/D3 若没有 Project Plan/阶段 UI 也不启动。

当前没有修改 UI，只改 `text/plain` 内容。
