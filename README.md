# Todo Assistant

**为 DSH 会话中的旁支任务保存上下文，并在需要时把它交接给未来的会话。**

开发时，你可能突然发现一个
Bug、想到一项配套功能，或意识到当前实现还缺少某个步骤。但主任务正在进行，你不想现在中断；等以后回来处理时，也不想重新调查一遍，更不想再次向
AI 解释来龙去脉。

Todo Assistant 让你先把这件事记下来。AI
会整理与该任务相关的必要信息，任务卡片可以在之后被查看、补充，并带入新会话或当前输入框。

它不只是记录"还有什么没做"，也帮助保留"为什么要做、之前已经知道什么、下一步该做什么"。

## 适合哪些场景？

### 发现 Bug，但暂时不修

你正在实现一个大功能，顺手发现了另一个模块的问题。先把问题和相关线索记下来，继续完成当前主任务；之后再单独处理。

### 想到配套功能，不想打断主线

实现过程中，你发现还需要一个设置项、一个编辑入口，或某个补充流程。先记录想法，等当前阶段完成后再回来处理。

### 把任务交给另一个会话

当你准备处理一张卡片时，可以让插件新建一个会话，并把卡片内容作为开场上下文；也可以将提示插入当前会话的输入框，由你决定何时发送。

### 减少重复调查和重复说明

卡片可以保留开发者的原始请求、任务相关信息、文件路径、下一步、必读内容和补充记录。必要时还可以按需回读原始会话中的指定片段，而不是一开始就把整段历史全部塞进上下文。

## 核心工作方式

-   **先捕获，再处理。** 记录旁支任务不要求你立刻离开当前工作。
-   **只保留相关信息。**
    卡片围绕当前待办组织信息，避免把主任务的全部上下文无差别复制进去。
-   **按需读取原文。**
    原始会话内容可以先查看目录，再选择需要的片段；回读成本较高，因此不会被当作普通的每轮提醒。
-   **交接由你决定。**
    可以新开会话，也可以插入当前输入框；插入操作不会自动发送。
-   **创建需要明确同意。** AI
    不应擅自创建待办。使用标记语法本身即表示你同意记录。
-   **提醒保持轻量。**
    插件根据当前会话访问的文件路径与该会话创建的未完成卡片做粗略相关性匹配，不需要每轮调用模型。

## 快速开始

### 1. 安装

在 DSH 中执行：

``` text
plugin_manager install_bundle  target = https://github.com/zangoose335/dsh-todo-assistant.git
```

`install_bundle` 需要审批，并且安装后需要重启
DSH。也可以从本地仓库安装，或按需固定到某个 Git commit。安装细节见下文。

### 2. 在右侧栏打开插件

在右侧栏点击 `+`，选择 **Todo Assistant**。

卡片按工作区查看；不属于任何工作区的卡只在
「全部工作区」视图里可见。侧栏提供未完成、待修复、待添加、已完成和全部等视图。

### 3. 记录一项旁支任务

你可以直接告诉 AI
希望记录什么，并明确同意创建；也可以使用下面的标记语法。同一条回复里可以放多个标记，一次记录多个待办。

``` text
#MEMO 会议记录完成后需要支持修改标题。先完成当前主功能，之后再实现标题编辑，并确认修改后的标题能正确保存和显示。
#/MEMO
```

`#DB` 和 `#MEMO` 都是待办标记，作用相同；`DB`
是"待办"的拼音首字母，`MEMO`
是更容易被国际用户理解的替代写法。**它们不代表不同的任务类型。** AI
应根据内容判断这是待修复问题、待添加功能还是其他事项。

标记规则：

-   `#db`、`#DB`、`#memo`、`#MEMO` 不区分大小写。
-   使用 `#DB … #/DB` 或 `#MEMO … #/MEMO`
    成对包住要记录的内容；结束标记可以省略，此时记录到消息末尾。
-   代码围栏和行内代码中的标记会被忽略。
-   标记内容表示开发者已同意记录，AI 不需要再次询问是否创建。
-   没有标记时，AI 仍必须先得到开发者明确同意，不能自行创建待办。

输入框支持 `#db` / `#memo` 的轻量补全。AI
回复上的"记录待办"面板也可以帮助选择回复中的段落并送入捕获流程。

## 卡片包含什么？

每张卡片首先是一份**任务简报**，再附带来源与现场：

-   **目标（goal）**：要解决什么问题、实现什么需求；
-   **背景（why，可选）**：为什么需要它；
-   **已确认事实与决定（confirmed）**：每条都标出可信度；
-   **约束（constraints）**：实现时不能违反的条件；
-   **线索（leads）**：文件、符号或文档路径，只作辅助；
-   **下一步（nextAction）**：开始执行时先做什么；
-   **待确认（openQuestions，可选）**：尚未确认、可能影响执行的问题。

`brief.nextAction` 是唯一的规范下一步。旧字段 `nextStep` 作为兼容镜像保留：只提供
brief 可以建卡，只提供 nextStep 仍兼容；两者冲突时以 brief 为准并返回 warning，任何正常写入都会同步二者。

简单任务可以只有 goal + nextAction，不要求填满其他字段。每条 brief 信息必须标明
`requirement`（开发者要求）、`decided`（已确认决定）、`verified`（已验证事实）、
`inferred`（AI 推断）、`unknown`（未知）或 `superseded`（已被替代）；推断不会被写成已确认事实。

旧卡没有 brief 时，插件从 `core`、`mustRead`、`park` 和 `touchedFiles` 派生只读简报。派生信息只用于读取，
不会批量改写旧数据；旧卡的可信度默认按 `unknown` 处理，不能当成已验证事实。

开发者原话由 Host 从用户消息中保存，不依赖 AI 转述，因此可以用来核对 AI
是否误解了原始需求。带 `#DB`/`#MEMO` 标记时，标记内的文本会完整保存；没有标记时，AI 只摘取与当前待办有关的那几句。若模型没有给出摘录，多段消息只保存第一段；第一段只是创建指令时不保存 request。

## 处理任务与交接上下文

打开卡片后，你可以选择：

-   **新会话中处理**：创建一个新会话，并将卡片整理成开场上下文。开场会要求先读代码/资料并给出方案，不直接改文件；确认方案后再实现。处理中需要你决定时，会在任务过程中使用 DSH 的提问面板，而不是等到最后才问。
-   **插入当前会话**：将一条处理提示插入当前输入框。它只会预填，不会自动发送；需要你决定时，同样会在处理过程中提问。

处理完成后，AI 应询问你是否将卡片标记为完成；得到确认后才更新状态。

卡片也支持追加
note，以记录新证据、进度或补充事实，而不是悄悄覆盖原始记录。

## 上下文读取与提醒

### 分层读取

-   **索引**：快速查看标题、状态和类型。
-   **卡片**：先读任务简报（目标/背景/已确认事实/约束/下一步/待确认），再按需看必读信息、文件和补充记录。
-   **原始会话**：先查看可回读消息的目录，再选择指定片段读取。

原始会话回读可能消耗较多 token。插件的工具说明要求 AI
先征得开发者同意，再查看目录并读取指定片段。手动创建、没有原始会话范围的卡片可能无法回读原文。

### 相关性提醒

插件会收集当前会话中的部分文件工具路径，并与该会话创建的未完成卡片比较。如果文件路径完全相同，或共享足够长的目录前缀，侧栏可能显示"相关"标记，并在后续步骤提醒
AI。

这是一种**轻量路径信号**，不是语义级的任务理解，也不能保证发现所有相关修改。它主要用于提示
AI：如果本轮产生了值得保留的新证据，可以通过 note 追加到卡片。

## 其他功能

-   按工作区查看；不属于任何工作区的卡在「全部工作区」中显示；
-   近似重复待办检测：共享文件是前提，标题或任务目标相似可辅助命中；同一文件但目标不同不会仅因标题相似被拦截；
    命中只是提示，不会自动合并或取消创建；开发者确认创建后可用 `forceCreate` 继续，确认补充则用 `todo_note`；
-   短编号，例如 `#3.2`，便于在对话中引用卡片；
-   `#` 引用选择器：正常会话中候选按当前会话所属工作区筛选；缺少会话 ID 时退回查询全部工作区；
-   每个工作区独立的通用规则，并在插件创建新会话时带入；
-   卡片状态、补充记录和原始上下文回读工具。

## 安装方式

所有方式都通过 `plugin_manager install_bundle` 安装，并且需要审批。

**从 GitHub 安装：**

``` text
plugin_manager install_bundle  target = https://github.com/zangoose335/dsh-todo-assistant.git
```

**从本地仓库安装：**

``` text
plugin_manager install_bundle  target = <仓库的绝对路径>
```

**固定到某个 commit：**

``` text
plugin_manager install_bundle  target = https://github.com/zangoose335/dsh-todo-assistant.git#<commit>
```

如果未来发布到 npm，也可以按包名和版本安装。`install_bundle` 需要 `pnpm`
位于 PATH 中。

安装或更新 Host 侧代码后，重启 DSH 以加载插件。只修改 `client.js`
时通常刷新页面即可。

安装后，在右侧栏点击 `+`，选择 **Todo Assistant**。
